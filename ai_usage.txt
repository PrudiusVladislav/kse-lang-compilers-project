⏺ Your question: new nodes or rewrite after parsing?

  Go with new nodes. Three things in the current compiler.py decide it:

  1. Name resolution already uses decl objects. VarNode, FieldAccessNode and
     AssignNode all get a .decl from lookup(), and codegen finds their memory
     with self.slots[decl]. With new nodes, a field name inside a member
     function falls through lookup() to the struct's by_name and returns a
     FieldNode. Codegen then builds a gep on this instead of reading slots. The
     existing field_ptr(base, [field.index] + indices) already produces that IR.
     A rewrite would need a fake this decl whose "slot" is a pointer argument
     rather than an alloca, so it fights the existing model.
  2. The mutation rule needs to know where an assignment points. "Assigns to a
     field of its object" falls straight out of decl being a FieldNode. After a
     rewrite, this.x looks like any other field path, and you would have to
     recover that information.
  3. --ast and error positions. The handout's dump shows MemberFn and
     MemberCall, so a rewrite could only run after the dump. Every synthesised
     this.x or Point_shift(p, 2) would also need copied line:col from the
     original tokens, or errors would point at the wrong place.

  The name-collision concern is already handled. Global functions are emitted as
  fn_{name}, and fn is a keyword so no struct can be called that. Point_shift
  therefore can't collide with any user function. There is one small remaining
  edge case: struct A_b with member c and struct A with member b_c both become
  A_b_c, and llvmlite raises DuplicatedNameError. I'd accept that risk, or
  reject it in collect if you want it closed.

  M3. Semantic: collection (collect)
  - Pass 1: all structs and fields, as now.
  - Pass 2: for each struct, its methods.

    - Store them in struct.methods_by_name.
  - Pass 3: global functions, as now.
  - Every signature has to exist before any body is checked. Methods call
    globals, globals call methods, and methods call each other in cycles.

  M4. Semantic: names inside a member function
  - Add self.current_struct. It is set together with current_fn in a new
    visit_member_fn(node), which mirrors visit_fn.
  - lookup(node) checks the scopes first, then current_struct.by_name, then
    raises the error. That gives the shadowing rule for free.
  - visit_call: when current_struct is set, try current_struct.methods_by_name
    before self.funcs.
    - If it hits, mark node.on_this = True.
    - Append the callee to current_fn.self_calls.
  - visit_assign:
    - If node.decl is a FieldNode of current_struct, set current_fn.mutating =
      True.
    - The existing mutable checks on the root and the path already cover
      "assignment to a const field".
    - Note that decl is a FieldNode here, so node.decl.mutable means the field's
      own mut. That's correct.

  M5. Semantic: visit_member_call(node) (after visit_call)
  - Type the object with obj.accept(self).
  - If the root name resolves to a struct name rather than a variable, report
    "call on a type" at the root. To make that error readable, check
    self.structs before the generic "used before its declaration".
  - If the type is not a struct, report "call on i32" at the method name.
  - If the method is missing, report "Circle has no member function 'd2'".
  - Arity and argument types work as in visit_call.
  - Record node.links: one mutable flag for the root decl and one per field in
    the path.
    - Inside a member function, a root that is a field of this counts as a link
      with that field's own mut.
    - If the root is this itself (a bare d2() call), there are no links.
  - If every link sits on this (the root decl is a FieldNode of current_struct),
    also append the callee to current_fn.self_calls. That handles
    center.shift() propagating.
  - Push node onto self.pending_calls. The mut check has to wait for the
    fixpoint.

  M6. The mutation rule (end of visit_program, after all bodies are checked)
  - Fixpoint: repeat over all methods until nothing changes. A method that isn't
    mutating but has any mutating callee in self_calls becomes mutating.
  - Then for each pending call where node.method.mutating is true, find the
    first link that is not mut and raise the error at it. The root token covers
    a const object; a path token covers a const field. The error is "cannot call
    mutating 'shift' on 'q': it is not mut".

  M7. CodeGen: the this pointer
  - visit_program:
    - After setting struct bodies, declare every method as ir.Function(module,
      FunctionType(ret, [ptr(struct_ty)] + param_tys), name=f"{S}_{f}"), before
      the global functions are declared. Store it in self.functions[method],
      keyed by node as now.
    - Emit the method bodies before the global ones.
  - visit_member_fn(node):
    - Call enter_function.
    - Set self.this = function.args[0] and name it this. It doesn't need an
      alloca, because it is never reassigned.
    - Parameters come from args[1:] and are spilled to allocas as now.
    - Set self.this = None for main and for global functions.
  - place(decl, indices), a new helper next to field_ptr, returns the address of
    a name.
    - If decl is a FieldNode: one gep on this with [0, decl.index, *indices].
    - Otherwise: field_ptr(self.slots[decl], indices) as now.
    - Route visit_var, visit_field_access and visit_assign through it.
    - In IR words, x := x + dx becomes: gep this[0,0], load, add, gep this[0,0],
      store. That is exactly what the handout's demo bullet asks for.
  - visit_call: if node.on_this, prepend self.this to the arguments.
  - visit_member_call(node):
    - The object address is place(root decl, indices). That is the alloca for p,
      a gep for c.center, or a gep on this for center inside a method.
    - Coerce the arguments as in visit_call, then call S_f(addr, ...).
    - The object is never loaded, which is what makes 83 rather than 67 come
      out.
